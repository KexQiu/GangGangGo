# 移动端同步

`SyncCoordinator` 是唯一自动同步入口。它在启动、登录变化、本地记录变化和回到前台时收集原因，750ms 防抖，并保证同一时间只有一轮任务运行；运行期间的新变化合并为一次尾随同步。

权益刷新、完整记录、Push 注册和 Watch 状态互不依赖时并行执行。旧报告快照上传任务已移除，好友直接读取服务端每日汇总的授权投影。任一云端失败不得回滚本地 mutation。服务端查询通过 TanStack Query key 去重，会话切换时清空缓存。

完整记录使用 SQLite outbox 和服务端单调游标：本地事实与 outbox 在同一事务提交，服务端按 mutation ID 幂等接收，同一实体以最后被服务端接受的变更为准。所有登录用户都执行完整同步；Watch 操作由 `/me/entitlements` 返回的 `watchActions` 控制，增长阶段默认开放，付费模式可恢复订阅门槛。当前数据页从本地明细生成每日汇总，不再请求旧高级报告接口。

本地数据按 profile 隔离。首次登录会接管当前未归属记录，之后切换账号使用各自 profile；退出登录后切回新的未归属 profile。健康事实与每日汇总保留 90 天，自定义小信号常用项持续保留。

完整同步只读取一次已经发布的会话快照，并始终使用该 `profileId` 读取 outbox、应用远端记录和保存游标。账号切换使旧同步停止；同账号的正常令牌轮换不会误判为换号。HTTP 层在首次发送、刷新等待及重试时继续检查原身份，不能用新账号令牌重发旧 body。

同步响应的 outbox 确认、数据应用和游标写入，与本地 profile 切换共用副作用队列。若切换发生在一次本地写入期间，该写入仅完成在原 profile 上，之后再切换；尚未开始的旧代次写入和列表重载取消。本地列表加载也有独立的失效标记，旧加载结果不能覆盖新 profile。该机制不改变远端冲突策略；本地未提交编辑保护（R09）和服务端游标提交顺序（R21）仍待处理。
