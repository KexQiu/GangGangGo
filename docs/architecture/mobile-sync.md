# 移动端同步

`SyncCoordinator` 是唯一自动同步入口。它在启动、登录变化、本地记录变化和回到前台时收集原因，750ms 防抖，并保证同一账号会话只有一轮任务运行；运行期间的新变化合并为一次尾随同步。换号使旧任务展示失效，新账号可开始同步；旧网络操作仍受原会话归属检查保护。

权益刷新、完整记录、Push 注册和 Watch 状态互不依赖时并行执行。旧报告快照上传任务已移除，好友直接读取服务端每日汇总的授权投影。任一云端失败不得回滚本地 mutation。服务端查询通过 TanStack Query key 去重，会话切换时清空缓存。

完整记录使用 SQLite outbox 和服务端单调游标：本地事实与 outbox 在同一事务提交，服务端按 mutation ID 幂等接收，同一实体以最后被服务端接受的变更为准。所有登录用户都执行完整同步；Watch 操作由 `/me/entitlements` 返回的 `watchActions` 控制，增长阶段默认开放，付费模式可恢复订阅门槛。当前数据页从本地明细生成每日汇总，不再请求旧高级报告接口。

本地数据按 profile 隔离。首次登录会接管当前未归属记录，之后切换账号使用各自 profile；退出登录后切回新的未归属 profile。健康事实与每日汇总保留 90 天，自定义小信号常用项持续保留。

完整同步只读取一次已经发布的会话快照，并始终使用该 `profileId` 读取 outbox、应用远端记录和保存游标。账号切换使旧同步停止；同账号的正常令牌轮换不会误判为换号。HTTP 层在首次发送、刷新等待及重试时继续检查原身份，不能用新账号令牌重发旧 body。

同步响应的 outbox 确认、数据应用和游标写入，与本地 profile 切换共用副作用队列。若切换发生在一次本地写入期间，该写入仅完成在原 profile 上，之后再切换；尚未开始的旧代次写入和列表重载取消。本地列表加载也有独立的失效标记，旧加载结果不能覆盖新 profile。本地未提交编辑保护与冲突规则见 [R09 回归](./local-edit-sync-acceptance.md)，服务端游标提交顺序见 [R21 回归](./sync-device-service-boundaries-acceptance.md)。

任务明确区分成功、跳过与失败。“我的”将登录状态与记录同步分开展示，提供当前资料的待上传更改数量、最近完整同步时间和只重试记录同步的入口。本地数据页及同步摘要将读取失败与真实空数据分开，并保留同资料的上次成功结果供重试。

`data_sync_state.last_synced_at` 是游标写入时间；SQLite 版本 4 新增的 `last_completed_at` 只在整轮完成且待上传队列为空时写入，不把中间页或历史拉取时间视为完整同步。实现、竞态回归及设备验收边界见 [R17/R18 验收记录](./sync-status-read-recovery-acceptance.md)。
