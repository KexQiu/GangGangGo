# R17/R18 同步状态与读取恢复

日期：2026-09-29；基于 `5bc0133`。本批实现同步状态与读取恢复，原生交互及真实双设备同步仍待验收。

## 已实现

### R18：本地读取状态

- 数据总览不再用预先生成的 90 天零值数据掩盖首次读取失败。加载、失败、确认无记录与有记录分别呈现，失败可重试。
- 日详情独立显示加载与错误；读取失败不会永久显示“正在读取”。同日期刷新失败保留上次读取结果并注明，换日期时不展示上一日明细。
- `LocalReadResource` 为总览、日详情和同步摘要提供统一的请求失效与会话检查。查询共用本地副作用队列，换号后不发布旧结果；关闭详情、页面失焦或更新请求后，迟到成功/失败均不能覆盖当前状态。
- 同一资料刷新保留已有结果，切换资料立即隐藏旧数据。账号恢复未完成时查询明确失败，避免恢复异常变成永久加载。

### R17：真实记录同步状态

- “我的”按本地会话显示是否已登录，账号资料读取与记录同步分别呈现。新增“记录同步”卡片，展示本轮状态、待上传更改数量、最近完整同步时间和记录同步重试。
- 完整记录、权益、Push、Watch 的协调器任务统一返回 `success` 或带原因的 `skipped`，异常进入 `error`。不再把未登录、权限未开启、设备不支持、换号取消或发送失败当作成功。记录同步重试只请求 data 任务，不连带重新请求通知权限。
- 同账号最多一轮运行，变更合并成尾随同步；换号递增协调器代次、清空旧任务展示，并允许新账号开始任务。旧网络操作继续受原会话保护，迟到成功/失败不能更新新账号状态，也不会阻塞新账号的网络同步。同账号 token 轮换保留原任务。
- 待上传数量对当前 profile 的 outbox 做完整计数，不受每批 100 条上传限制；界面称“项更改”，同一记录多次修改可对应多项。待补充草稿没有进入 outbox，不计入该数量。
- 本地同步摘要读取失败显示独立错误和重试；已有数量会标注“上次读取”。登录、历史成功时间或零待上传均不能单独证明本轮已完成，页面需等待本轮同步确认。

## 持久化边界

SQLite 升至版本 4，`data_sync_state` 新增 `last_completed_at`。原 `last_synced_at` 只表示拉取游标写入时刻，可能只是中间一页；新字段不回填旧时间，避免把历史部分完成误报为整轮成功。

整轮上传、分页拉取、合并与本地重载结束后，使用原会话的本地队列及 SQLite 事务检查 outbox。仍有新增更改时保持待同步；没有待提交项且会话仍有效才写入完成时间。写入失败或写入期间换号会回滚时间；分页失败保留已安全提交的游标，但不更新完整同步时间。后续失败不抹去历史成功时间，错误状态仍优先展示。

数据库升级保留版本 1–3 的开发数据、草稿和游标。本批未增加依赖，也未修改服务端同步协议。
