# R11–R13 记录纠错与草稿恢复

日期：2026-09-29；基于已推送的 `d808123`。本批实现日详情编辑入口、结束计时草稿和固定事件时间；原生交互仍待设备验收。

## 实现与数据边界

- R11：数据页的日详情中，每条蹲会儿记录均有“编辑或删除”入口。关闭日详情后进入现有记录页；返回数据页重新读取统计。编辑、删除绑定加载记录时的会话代次，换号后的旧表单不能修改新账号。
- R12：点击“收工”先将待补充记录提交至 SQLite，再清除持久化计时。路由只携带草稿 ID；从“蹲会儿”的待补充列表恢复。表单字段变更自动保存，失败有反馈及重试；关闭或离开页面保留草稿，主动放弃需要确认。
- R13：点击“收工”的时刻固定为 `endedAt`，暂停时间不计入时长。延迟填写、跨午夜保存或手动修正时长均不改变原开始/结束时间，统计仍按结束日期归档。
- 正式保存时，记录、outbox、每日汇总及草稿完成状态在一个 SQLite 事务中提交。失败全部回滚，草稿仍可重试；重复提交与迟到自动保存不会产生第二条记录。
- 手机草稿与手表正式保存均写入计时完成标记。即使 KV 清理失败、重启恢复了旧计时，或两端先后结束同一次计时，也不能重复生成记录。标记读取与本地写入共用串行边界，不读取尚未提交的结果。
- 本次 SQLite 版本为 3，新增 `toilet_record_drafts`，不增加第三方依赖或云端接口。已有版本 1/2 开发库增量升级并保留数据。

草稿只保存在本机，未正式保存前不计入统计、不写入 outbox，也不上传。草稿按本地 profile 隔离；匿名资料绑定账号时随原资料一起归属该账号。读取和修改绑定资料归属及会话代次。仍在运行中的计时保留开始时的账号归属，换号后不能直接保存到新账号，需要回到原账号或放弃该计时。

草稿以结束时间为基准最多保留 90 天，过期后不可继续保存，随当前资料的本地健康数据清理任务删除。保存或放弃后立即清空草稿正文，只保留 ID、资料归属、起止时间和完成状态以防重放，亦受同一清理窗口约束。登录前同步说明已补充草稿边界。

- 收工先落草稿，不提前产生正式记录、统计或 outbox；重复点击固定第一次结束时间。
- 暂停、延迟填写、跨午夜保存，草稿内容恢复及最终归档时间。
- 草稿创建失败保留运行计时；KV 清理失败后恢复旧计时，不丢草稿或重复保存。
- 正式记录、outbox、汇总、完成标记任一步失败，全事务回滚后可重试。
- 主动放弃、迟到自动保存、重复正式提交以及删除正式记录后的旧提交重放。

- 日详情所用查询在编辑/删除后反映正确统计，并产生对应同步 outbox；未进行真实云端双设备同步。
