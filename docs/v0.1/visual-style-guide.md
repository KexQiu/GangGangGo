# 小提督整体风格设计指南

版本：v0.1
日期：2026-05-22
阶段：v0.1 当前视觉与文案规范
关联文档：[产品定位文档](./product-positioning.md)、[PRD](./prd-v0.1.md)

## 1. 设计定位

小提督的整体风格是：

**轻松克制、隐私友好、可信赖的私密健康习惯工具。**

它不是医院 App，也不是恶搞 App。界面要让用户敢打开、愿意每天点一下，并且在风险场景中知道应该认真处理。

## 2. 当前体验原则

### 2.1 单首页优先

当前 App 不使用底部 Tab。首页就是今日行动中心，用户打开后应能完成大部分高频动作：

- 看今日状态和今日正反馈。
- 开始菊花抬。
- 开始蹲会儿。
- 快速小账本打卡。
- 进入最近小报告。
- 查看小暗号和小花说明书。

### 2.2 轻松但不低俗

可以使用“小花、开张、下班、收工、小暗号、小账本、小报告”等轻松表达，但不能出现低俗段子、身体羞辱或夸张恶搞。

### 2.3 正反馈但不强游戏化

正反馈要让用户感到“做了一点也有价值”，但不使用积分、等级、排行榜、金币、烟花或强刺激动效。

### 2.4 风险场景严肃

明显便血、明显不适、剧烈疼痛、症状加重等场景必须清晰表达，并建议咨询医生。此类场景不使用庆祝文案。

## 3. 视觉关键词

- 温和
- 清爽
- 私密
- 轻松
- 工具感
- 低负担
- 有完成感
- 不制造焦虑

## 4. 不采用的风格

### 不做医疗恐惧风

避免病理图片、医生插画、大面积红色、医院病历感。

### 不做低俗搞笑风

避免夸张身体部位、黄色段子、过度拟人化器官。

### 不做健身热血风

避免挑战极限、排行榜、连续打卡压迫、燃烧卡路里式成就。

### 不做复杂数据风

最近小报告只展示轻量趋势，不做医疗分析、健康评分或复杂报告。

## 5. 色彩系统

当前颜色 token 位于 `apps/mobile/src/theme/colors.ts`。页面必须通过 theme token 使用颜色，不直接写死色值。

当前主色方向为 **清爽绿色健康工具风**：浅绿背景、绿色主行动、蓝色信息、紫色隐私、橙色警示、红色风险。

### 色彩使用规则

- 主色用于菊花抬、完成状态、正反馈。
- 信息色用于普通提示和蹲会儿早期阶段。
- 隐私色用于小暗号和通知设置。
- 警示色用于蹲会儿长会、需要注意但非小信号的状态。
- 危险色仅用于明显便血、明显不适、就医提示等风险。
- 风险场景不能因为轻松文案而弱化，仍然必须使用 `danger`。

## 6. 组件规范

### Screen

- 页面背景使用 `colors.background`。
- 默认只包含顶部安全区。
- 无底部导航时，训练中和蹲会儿进行中页面可显式保留底部 safe area。

### AppTopBar

- 二级页统一使用。
- 顶栏固定在滚动内容外，返回/关闭按钮不能随页面滚动消失。
- 训练中、蹲会儿进行中使用关闭图标，并在中途退出时弹确认。

### AppCard

- 用于独立功能块。
- 不在卡片里嵌套卡片。
- 默认圆角 24，边框使用 `colors.border`。

### AppButton

- 主按钮表达明确动作，如“开始菊花抬”“开始计时”“记好了”。
- 次按钮用于设置、查看说明、精细记录。
- 风险动作不使用大红实心按钮。

### 状态标签

首页状态标签必须短，不塞完整句子：

- 菊花抬：待营业、已开张、已下班。
- 小账本：待开张、已记录、满格。
- 蹲会儿：未记录、已入账。

## 7. 核心页面规范

### 7.1 首页

首页目标：用户 3 秒内知道今天做了什么、下一步做什么。

顺序：

1. 标题和右上角设置。
2. 今日概览。
3. 未开启提醒时的小暗号前置引导。
4. 菊花抬主行动卡。
5. 蹲会儿紧凑入口。
6. 今日小账本快速打卡。
7. 最近小报告、小暗号状态、小花说明书等轻量工具入口。

视觉重点：

- 菊花抬是最大主行动。
- 小暗号未设置时应靠前提示，但视觉权重低于菊花抬。
- 最近小报告明显但不抢主行动。
- 小花说明书可见但不制造焦虑。

### 7.2 菊花抬

页面目标：让用户跟着节奏完成训练。

视觉规则：

- 训练中页面使用大倒计时。
- 收紧和放松阶段有不同提示。
- 完成页使用对勾、轻量 success haptic 和克制的成功动效。
- 不使用烟花、金币或夸张动效。

图标规则：

- 菊花抬使用同一套小花图标语言。
- 首页主入口使用标准模式小花抬图标。
- 新手、标准、快速三种模式通过弧线长度、节奏点、速度线区分。

文案示例：

- 轻轻抬一下。
- 好，放松。
- 呼吸在线，轻提，不用猛。
- 小花可以下班一会儿。

### 7.3 蹲会儿

页面目标：极简、防刷手机、及时收工。

状态文案：

- 刚刚蹲下。
- 小声敲门。
- 差不多该收工了。
- 蹲会儿长会了。
- 真的该收工了。

视觉规则：

- 普通阶段不用红色。
- 5 分钟使用 info。
- 10/15 分钟使用 warning，并让 15 分钟明显更像“已经偏久”。
- 20 分钟使用 danger。
- 便血、不适等小信号才使用 danger 风险语义。
- 不鼓励用户增加蹲会儿次数或时长。

图标规则：

- 首页和最近小报告使用 `Hourglass`，强调别待太久。
- 蹲会儿启动页使用 `Armchair`，表达短暂停留。
- 不使用直白马桶图标。

### 7.4 小账本

页面目标：快速记录，不像填问卷。

规则：

- 首页快速打卡一点即记为达标。
- 达标后再次点击可撤销。
- 首页显示短判断标准。
- 详情页三档滑块可调整。
- 未记录时不展开三档标准，只显示达标参考，避免卡片过长。
- 满格时突出“小账本满格”并触发轻量祝贺动效。
- 连续完整打卡可展示天数，但不做排行榜。

### 7.5 最近小报告

页面目标：让用户看到“最近确实有坚持”。

结构：

- 顶部小报告反馈卡。
- 近 7 天小报告。
- 近 30 天回看。
- 小信号提示卡。

趋势卡规则：

- 菊花抬：柱子代表每日完整完成组数。
- 小账本：柱子代表每日完成项数，满格日用主色。
- 蹲会儿：只展示是否记过；长会用 warning，小信号用 danger。
- 无记录时显示空状态，不显示空图表。

### 7.6 小暗号设置

页面目标：让用户相信提醒不会尴尬。

文案方向：

- 小暗号。
- 小花锻炼。
- 换个姿势。
- 闭麦时间。

交互规则：

- 支持菊花抬提醒和久坐提醒。
- 支持隐私模式。
- 支持多段勿扰，包含午休和夜间共存。
- 隐私模式下避免出现“提肛”“肛门”等敏感词。

### 7.7 小花说明书

页面目标：轻松说明，但风险信号明确。

模块：

- 怎么抬比较不费戏。
- 这些时候先让小花下班。
- 这些信号问专业队友。
- 常见小翻车。

风险文案必须清楚：

- 明显便血。
- 剧烈疼痛。
- 不适加重。
- 建议咨询医生。

## 8. 文案语气

总体语气：

- 短。
- 轻。
- 清楚。
- 有边界。

当前术语：

| 术语 | 含义 |
| --- | --- |
| 菊花抬 | 提肛训练 |
| 小花 | 对训练部位的轻松隐喻 |
| 小暗号 | 隐私提醒 |
| 蹲会儿 | 如厕时间计时 |
| 收工 | 结束蹲会儿计时 |
| 小账本 | 健康习惯打卡 |
| 最近小报告 | 7 天趋势和 30 天摘要 |
| 小花说明书 | 安全说明 |
| 开张 | 今天已经开始记录或训练 |
| 下班 | 今日建议量已完成 |
| 长会 | 蹲会儿超过 15 分钟 |
| 小信号 | 便血或明显不适 |

可以使用：

- 今天不是空白页。
- 小花已开张。
- 小账本满格。
- 收工已入账。
- 今天不用卷了。
- 知道就好，下次早点散会。
- 先问专业队友，建议咨询医生。

避免使用：

- 挑战极限。
- 冲榜。
- 打败多少人。
- 治好痔疮。
- 根治便秘。
- 你可能得了某某病。
- 不练就会出问题。

## 9. 动效和反馈

原则：

- 轻、短、稳定。
- 不制造兴奋或压力。
- 正反馈是确认感，不是游戏奖励。

当前反馈：

- 按钮和入口按下轻微缩放。
- 小账本满格时使用克制的 SuccessBurst 和 haptic。
- 菊花抬完整完成使用 success haptic 和成功动效。
- 蹲会儿阶段切换前台使用 haptic 和短音效。
- 蹲会儿音效遵循系统静音，不强制绕过静音。
- 蹲会儿记录无风险保存时使用正反馈文案。
- 风险场景不使用庆祝反馈。

## 10. 可访问性

- 点击区域不小于 44。
- 状态不能只靠颜色表达，必须有文字。
- 深色模式下 warning 和 danger 要保持可读。
- 大倒计时要稳定，不因数字变化导致布局跳动。
- 小柱状图必须有数字和日期标签辅助理解。
- 风险提示不能只用红色表达。

## 11. 设计资产说明

`docs/archive/previews/` 中的早期预览图仅作为历史参考，不是当前 UI 的实现标准。

当前 UI 的真实标准以以下内容为准：

- 本风格指南。
- `apps/mobile/src/theme/colors.ts` 的主题 token。
- 当前 App 页面实现。

后续如需生成视觉预览，应优先使用位图预览，不以 SVG 作为最终视觉交付。

## 12. 当前设计结论

小提督当前设计方向是：

**单首页承载高频动作，用轻松文案降低尴尬，用今日反馈和最近小报告提升坚持感，用小花说明书守住健康边界。**

后续设计新增功能时，应优先检查：

1. 是否让首页更复杂。
2. 是否让用户更尴尬。
3. 是否暗示治疗效果。
4. 是否鼓励过度训练或过度记录。
