# 好友关系重构

本文件是 v0.2 社交关系的当前实现说明，取代旧文档中的“小队”“监督搭子”“共享快照”和 Pro 好友门槛。

## 产品规则

- 所有已登录用户均可添加好友，不要求 Pro。
- 好友邀请单次有效，接受后建立双向关系；每个用户最多 20 位好友。
- 新关系默认不共享菊花抬、小账本或蹲会儿数据。
- 每段关系按拥有者方向独立配置三类数据的 `不可见 / 低敏 / 完整` 权限，可见周期为 `1 / 7 / 30` 天。
- 固定提醒保留，每位接收者可按好友设置开关、每日上限和勿扰时间。
- 蹲会儿结束通知需要发送方和接收方各自开启对应开关；勿扰时间只抑制 Push，不删除应用内事件。
- 删除好友是硬删除，关系、设置、互动、回执和关系内提醒计数级联清除。

## 隐私投影

服务端从 `daily_activity_summaries` 读取数据，并按数据拥有者对当前好友的设置裁剪：

- 菊花抬低敏只返回是否达标，完整返回次数、重复数和总时长。
- 小账本低敏只返回完成度和连续天数，完整返回四项等级。
- 蹲会儿低敏只返回是否记录，完整返回聚合次数、时长、形态、颜色、感受、小信号和需留意统计。

客户端不会收到未授权字段，不能通过隐藏 UI 代替服务端鉴权。

## 蹲会儿结束事件

完整记录首次被云端同步后，数据同步服务调用好友事件服务。事件以好友关系、发送者、接收者和本地记录 ID 唯一，重试不会生成重复时间线事件。开关开启前结束的记录不会补发。只有接收者拥有完整蹲会儿权限时，事件和 Push 才包含时长。

## 当前接口

接口清单以 [API 参考](./api-reference.md) 为准。旧 `/teams`、`/team-invites`、`/share-settings`、`/share-snapshots`、`/nudges` 和 `/buddy-nudge-settings` 路由均已下线。
旧小队、共享快照与搭子提醒的表、枚举、服务、契约和客户端代码不保留兼容层，由数据库迁移直接删除。
