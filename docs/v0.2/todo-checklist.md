# 小提督 v0.2 待办清单

版本：v0.2
日期：2026-05-26
阶段：开发联调版

## 1. 当前判断

v0.2 已完成后端基础、移动端接入骨架、账号页、小队页、搭子提醒页、高级小报告入口和头像上传骨架。当前状态适合继续开发联调，但还不适合生产上线。

后续优先级应按“可测试闭环 -> 生产级能力 -> 原生能力”推进。

这些事项不完成，会影响当前 v0.2 云端功能的完整手动测试。

  - 建议位置：`我的` 页开发登录区域。
  - 建议用户：`mock-user-a`、`mock-user-b`、`mock-user-c`。

- [ ] 完成小队邀请双用户完整联调。
  - 用户 A 创建小队并生成邀请。
  - 用户 B 接受邀请。
  - 双方能看到成员和低敏状态。
  - 双方能互发搭子提醒并回执。

- [ ] 验证共享快照自动上传触发点。
  - App 启动。
  - App 回到前台。
  - 菊花抬完成。
  - 小账本变化。

- [ ] 验证高级报告快照上传。

  - `/reports/advanced?range=90d` 能读到新数据。

## 3. P1：生产级后端能力

这些事项不影响本地联调，但上线前必须完成。

- [ ] 接入正式对象存储 provider。
  - 可选：阿里云 OSS、腾讯云 COS、七牛云、Cloudflare R2、S3 兼容服务。
  - 后端替换 `AvatarStorageService` 实现。
  - `POST /me/avatar-upload` 返回真实预签名上传 URL。
  - 数据库继续只保存 `avatar_url`。

- [ ] 增加真实 Postgres 集成测试。
  - 覆盖用户 upsert。
  - 覆盖小队创建、邀请、接受。
  - 覆盖共享快照和报告快照。
  - 覆盖搭子提醒、提醒设置、回执。

- [ ] 加固搭子每日提醒次数并发一致性。
  - 当前逻辑仍可能在并发请求下超出每日上限。
  - 可选方案：事务锁、每日计数表、数据库唯一约束。

- [ ] 加固小队人数上限并发一致性。
  - 当前多个邀请并发接受时，仍需要数据库级保护。
  - 目标：每队最多 owner + 3 个搭子。

- [ ] 增加 API 速率限制。
  - 重点保护：登录、创建邀请、发送搭子提醒、头像上传地址。

- [ ] 完善审计和数据保留策略。
