## 1. 当前状态

v0.1 本地健康闭环已完成并保留为免费能力：

- 菊花抬。
- 蹲会儿。
- 小账本。
- 小暗号。
- 最近小报告。
- 小花说明书。
- 灵动岛计时基础能力。

v0.2 当前已完成开发骨架：

- 后端 API、Postgres + Drizzle schema、OpenAPI 文档。
- 账号与权益基础链路。
- 小队、邀请、共享快照、搭子提醒、回执。
- 头像上传对象存储骨架，当前使用 mock storage。
- 移动端 API client、会话 store、我的页、Pro 页、小队页、提醒页。
- WatchConnectivity iPhone 桥接、Watch App target、Watch 页面、离线队列、ACK、开发调试面板。
- Watch Complication 已接入共享低敏状态、过期态、Pro 锁定态、蹲会儿深链和三种表盘样式。

当前仍是 **开发联调版**，不适合生产上线。核心阻塞是：

- 真实订阅购买与 App Store Server 校验未完成。
- 真实 Sign in with Apple、Push 和部分 Live Activity 能力受 Apple Developer Program 和签名能力限制，当前部分关闭或未验收。
- Apple Watch 已完成真机初步测试，仍需完整手动清单留痕和表盘 / haptic 专项验收。
- 正式对象存储、生产部署、集成测试和并发一致性加固未完成。

## 2. 优先级定义

- `P0`：当前联调闭环必需，不完成会阻碍 v0.2 功能验证。
- `P1`：生产上线必需，不完成不应进入公开测试或上架。
- `P2`：体验增强或商业化加分项，可在主链路稳定后推进。
- `P3`：后续版本考虑，不进入 v0.2 主线。

### 3.4 高级报告快照联调

状态：代码已完成，待手动验收和生产联调
目标：Pro 用户能批量上传最近 90 天个人高级报告摘要，并在高级小报告读取 90 天每日序列和汇总。

已完成：

- 保留 `PUT /report-snapshots/today` 单日上传接口。
- 新增 `PUT /report-snapshots/bulk` 批量上传接口，单批最多 90 条。
- Pro / 宽限期用户可上传；免费用户访问返回 `403`。
- 批量上传按 `user_id + date` upsert，同一批内同一天重复数据保留请求内最后一条。
- `GET /reports/advanced?range=90d` 返回用户时区内最近 90 天窗口、升序 `days`、`summary` 和兼容旧 UI 的最新 `snapshot`。
- 高级报告快照只给本人使用，不进入小队共享。
- 移动端已将今日同步升级为最近 90 天批量同步，非登录或非 Pro 直接跳过。

待办：

- [ ] 手动走查免费用户、Pro 用户、宽限期用户和过期用户访问结果。
- [ ] 用真实数据库确认同一用户同一天重复上传会更新旧记录。
- [ ] 验证超过 90 条、日期格式错误、计数字段越界时整批拒绝。
- [ ] 确认 App 启动、登录后、回到前台、训练/小账本/蹲会儿数据变化时同步不会影响基础小报告。

验收标准：

- Pro 用户能看到 90 天回看入口，并能读取 90 天每日序列。
- 免费用户进入 Pro 引导。
- 云端失败不影响本地记录保存和基础小报告。
- 小队成员无法看到 `daily_report_snapshots` 内容。
